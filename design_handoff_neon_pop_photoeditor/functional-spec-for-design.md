# AuroraPhotoEditor — техническое описание для дизайна UI

## 0. Контекст (для нейросети, которая будет проектировать дизайн)

Это мобильное/планшетное приложение для **Aurora OS** (форк Sailfish OS, российская мобильная ОС). Технологии: **Qt5 QML** (UI) + **C++ бэкенд** (обработка изображений через OpenCV и ONNX Runtime для ML-инференса). UI-фреймворк — **Sailfish Silica** (родная компонентная библиотека Aurora/Sailfish: `Page`, `PageHeader`, `PullDownMenu`, `DockedPanel`, `SilicaFlickable` и т.д. — свайповая навигация, pull-down меню сверху страницы вместо гамбургер-меню, минималистичная плоская эстетика).

**Задача:** спроектировать дизайн этого приложения заново, **не потеряв ни одной существующей функции**. Ниже — исчерпывающее описание каждого экрана: что он делает, с чем взаимодействует, какие данные/сигналы связывают его с остальным приложением. Отдельно указано, какой функционал уже есть в бэкенде, но пока не подключён к UI (заглушки) — под него тоже нужно заложить место в дизайне.

Дизайн не обязан копировать визуальный стиль Sailfish Silica один в один, но должен сохранить **весь перечисленный функционал и переходы между экранами**.

**Целевое устройство:** планшет Aurora OS **F+ T1100**, экран 1600×2176 px, ~11", плотность ~244 PPI, `theme_pixel_ratio=1.25`, поддерживаются портретная и альбомная ориентации. Дизайн должен быть адаптирован под это разрешение и работать в обеих ориентациях.

---

## 1. Общее назначение приложения

Простой фоторедактор с **неразрушающим (non-destructive) конвейером правок**: пользователь выбирает фото из галереи устройства, применяет к нему одну или несколько операций (пока в UI живая только одна — "Улучшение"), может отменить последнюю операцию или сбросить всё к оригиналу, и сохраняет результат обратно в галерею.

Ключевая архитектурная идея: есть **оригинал** (original) и **текущее** (current) изображение. Каждая применённая операция — это команда (`ImageEditorCommand`), которая добавляется в стек. Undo — просто откат на шаг назад по стеку и пересчёт текущего изображения из предыдущего состояния (не пересчитывается заново, а хранится готовый результат каждого шага).

## 2. Структура приложения (дерево экранов)

```
ApplicationWindow (AuroraPhotoEditor.qml)
├── cover: DefaultCoverPage.qml           — обложка в списке "открытых приложений" (multitasking)
└── initialPage: MainPage.qml             — главный/единственный рабочий экран
      ├── → ImagePickerPage (системный)   — выбор фото из галереи (пуш на стек)
      ├── → AboutPage.qml                 — "О приложении" (пуш на стек)
      └── → NoticePage.qml                — экран результата (успех/ошибка) после сохранения
```

Навигация — классический для Sailfish **page stack** (стек страниц, переходы свайпом справа налево = "назад", программно `pageStack.push(...)` / `pageStack.pop()`). Экран не имеет вкладок/боковых меню — всё линейно, стек одного потока.

## 3. Экран за экраном

### 3.1. `AuroraPhotoEditor.qml` — корневое окно приложения
**Назначение:** точка входа, ничего не рендерит сама — просто хост для стека страниц.
**Функционал:** задаёт стартовую страницу (`MainPage`), обложку для многозадачности (`DefaultCoverPage`) и разрешённые ориентации экрана (все, включая портрет и ландшафт).
**Взаимодействие:** ни с чем напрямую — это контейнер верхнего уровня.

---

### 3.2. `DefaultCoverPage.qml` — обложка приложения (Cover)
**Назначение:** миниатюра приложения, которая показывается в системном экране "открытые приложения" (аналог multitasking-превью в iOS/Android, но в Sailfish это отдельный маленький QML-компонент, а не скриншот).
**Функционал:** статичная карточка — иконка приложения + название "App" / "PhotoEditor".
**Взаимодействие:** сейчас не отражает состояние приложения (не показывает превью текущего фото, нет быстрых действий/кнопок на обложке — хотя Sailfish это поддерживает через `CoverActionList`, тут не используется).
**Для дизайна:** это самое маленькое "окно" в проект — по сути визитка приложения в свёрнутом виде.

---

### 3.3. `MainPage.qml` — главный (и единственный полноценный) рабочий экран
Это сердце приложения — всё редактирование происходит здесь, без перехода на отдельные "страницы редактора".

**Структура экрана (сверху вниз):**

**a) Шапка (`PageHeader`)**
- Заголовок: "PhotoEditor"
- Четыре иконки-кнопки справа в шапке:
  1. **Undo** (иконка "отменить") — активна только если есть что отменять (`canUndo`). Откатывает последнюю применённую операцию.
  2. **Reset** (иконка "обновить/сброс") — активна тоже только при `canUndo`. Сбрасывает изображение к оригиналу, стек операций очищается полностью.
  3. **Save** (иконка "сохранить") — видна только если фото загружено (`hasImage`). Экспортирует текущее изображение в галерею устройства.
  4. **About** (иконка "о приложении") — всегда видна. Открывает `AboutPage`.

**b) Pull-down меню** (потянуть экран вниз от шапки — стандартный Sailfish-паттерн для контекстных действий)
- Пункт "Select Photo" — открывает системный выбор фото из галереи.

**c) Основная область — три взаимоисключающих состояния:**
  1. **Пусто (нет фото)** — по центру: иконка изображения, текст "No photo selected" и кнопка "Select Photo" (дублирует функцию pull-down меню, для пользователей, которые не знают о свайпе вниз).
  2. **Фото загружено** — само изображение, вписанное в экран с сохранением пропорций (`PreserveAspectFit`), с отступом снизу под панель инструментов. Смена фото анимируется плавным fade (400 мс).
  3. **Идёт обработка** — поверх всего крутится `BusyIndicator` (спиннер), пока `isProcessing == true` (асинхронная операция выполняется в фоновом потоке).

**d) Панель инструментов (`DockedPanel`, прикреплена снизу)**
- Появляется/раскрывается автоматически, когда фото загружено (`open: hasImage`).
- Три кнопки в ряд: **"Фон"**, **"Улучшение"**, **"Стиль"**.
- ⚠️ **Важно для дизайна:** сейчас это заглушки — по клику просто пишут в консоль (`console.log`), реального перехода/действия нет. Но по бэкенду понятно, что задумано:
  - **"Улучшение"** — единственная операция, у которой уже есть готовая backend-логика (`EnhanceCommand`): автоматическая коррекция экспозиции/контраста через CLAHE (адаптивное выравнивание гистограммы) в LAB-пространстве + автоматический баланс белого (Gray World). Без параметров — это операция "в один клик", не требует отдельного экрана с настройками (хотя дизайн может это предусмотреть).
  - **"Фон"** — предполагается работа с фоном фото (замена/удаление/размытие фона) — судя по названиям классов в проекте (`MLInferenceEngine`, ожидание `.onnx`-моделей), должна использовать ML-сегментацию. Backend-реализации пока нет.
  - **"Стиль"** — предполагается стилизация (style transfer) изображения через ML. Backend-реализации пока нет.
  - Значит, дизайну нужно заложить **что происходит при выборе каждого инструмента** — вероятно, отдельный подэкран/шторка с параметрами для "Фон" и "Стиль" (раз это не одношаговые операции), и, возможно, просто мгновенное применение для "Улучшение".

**Взаимодействие с объектами:**
- Вся логика идёт через глобальный контекстный объект `pipelineManager` (C++ `PipelineManager`, доступен из QML как singleton-контекст), у него:
  - Свойства (реактивные, автообновляют UI): `hasImage`, `canUndo`, `isProcessing`.
  - Методы: `loadFromUri(uri)`, `undoLast()`, `resetToOriginal()`, `exportImage()`.
  - Сигналы, на которые подписан `MainPage`: `currentImageChanged` (обновляет превью), `exportCompleted(success, filePath)` (открывает `NoticePage` с результатом).
- Само изображение подгружается через кастомный image-provider: `image://pipeline/current?t=<timestamp>` — таймстемп в URL нужен, чтобы Qt не закэшировал старую картинку при обновлении.
- Выбор фото открывает **системный** `ImagePickerPage` (компонент из `Sailfish.Pickers`, не часть этого проекта — стандартная страница-галерея ОС с гридом миниатюр и папками). После выбора файла путь передаётся в `pipelineManager.loadFromUri(...)`.

---

### 3.4. `AboutPage.qml` — "О приложении"
**Назначение:** статичная информационная страница.
**Функционал:** заголовок "About Application", блок с описанием приложения (сейчас placeholder-текст "Короткое описание моего приложения для ОС Аврора" — не заполнено разработчиками), заголовок-разделитель "3-Clause BSD License" и полный текст лицензии BSD-3-Clause.
**Взаимодействие:** ни с чем, кроме перехода "назад" (в page stack). Прокручиваемая (`SilicaFlickable`), т.к. текст лицензии длинный.

---

### 3.5. `NoticePage.qml` — универсальный экран-уведомление
**Назначение:** переиспользуемый экран для сообщения об итоге операции (сейчас используется только после сохранения фото, но написан универсально).
**Функционал:** по центру — иконка галочки ("acknowledge"), текст сообщения (передаётся параметром `message` при открытии страницы) и кнопка "OK", закрывающая страницу (`pageStack.pop()`).
**Взаимодействие:** открывается из `MainPage` с двумя возможными текстами:
  - Успех: "Image successfully saved to: <путь к файлу>"
  - Ошибка: "Failed to save image"
Никаких дополнительных данных/действий (например, "открыть файл" или "поделиться") сейчас нет — просто подтверждение и закрытие.

## 4. Сквозные (не завязанные на один экран) механики

- **Асинхронность:** любая операция редактирования выполняется в отдельном `QThread` (не блокирует UI), поэтому на экране обязательно должен быть индикатор "идёт обработка" (сейчас — `BusyIndicator`), и кнопки, которые не должны быть доступны во время обработки, должны это учитывать в дизайне (сейчас, например, можно нажать undo прямо во время обработки — это баг/недосмотр, дизайн может явно блокировать панель инструментов при `isProcessing`).
- **Отмена операции при переключении:** если пользователь запускает новую операцию, пока предыдущая ещё считается, старая просто отменяется (без уведомления пользователя) — это стоит учитывать: возможно, нужен явный UI-фидбек "предыдущая операция отменена".
- **Экспорт** сохраняет JPEG (качество 95) в системную папку "Изображения" с именем `AuroraPhotoEditor_<timestamp>.jpg`, без диалога "куда сохранить" — путь фиксированный, имя генерируется автоматически.
- **Защита от decompression bomb:** изображения крупнее 64 мегапикселей отклоняются на этапе загрузки (без сообщения пользователю в UI сейчас — просто ничего не происходит, что тоже стоит доработать в дизайне: нужен экран ошибки загрузки).

## 5. Что явно НЕ реализовано (но должно быть учтено местом в дизайне)

1. Реальные экраны/флоу для инструментов **"Фон"** и **"Стиль"** — сейчас только кнопки-заглушки.
2. Диалог/шторка настроек для инструментов (если "Фон" или "Стиль" окажутся многопараметрическими — например, выбор степени размытия фона).
3. Обработка ошибки "не удалось загрузить фото" (слишком большое изображение или битый файл) — сейчас никак не показывается пользователю.
4. Реальное содержимое `AboutPage` (описание сейчас — placeholder).
5. Просмотр истории операций (стек команд существует в бэкенде — `commandCount()`, но в UI нигде не отображается список применённых шагов, только один Undo на последний шаг).
