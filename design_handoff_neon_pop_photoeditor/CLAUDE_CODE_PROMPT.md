```
В папке design_handoff_neon_pop_photoeditor/ лежит дизайн-хендофф для UI моего приложения
AuroraPhotoEditor (Aurora OS, Qt5/QML, Sailfish Silica, C++ бэкенд с OpenCV + ONNX Runtime).
Прочитай по порядку:
1. design_handoff_neon_pop_photoeditor/README.md — полное описание экранов, токенов, поведения
2. design_handoff_neon_pop_photoeditor/functional-spec-for-design.md — функциональное ТЗ
   (какие сигналы/свойства есть у pipelineManager, как устроена навигация страниц)
3. design_handoff_neon_pop_photoeditor/architectural_plan_onnx.pdf — архитектурный план
   (слои 0-6, ISSUE-N.N задачи, на которые есть ссылки в README)
4. design_handoff_neon_pop_photoeditor/Aurora Variant 1 Neon Pop.dc.html — кликабельный
   HTML-референс дизайна «Neon Pop» — открой его в браузере, чтобы увидеть все экраны и
   переходы вживую. Это ТОЛЬКО референс визуального стиля и поведения — не копируй HTML/CSS
   код напрямую, а пересоздай экраны нативно на QML/Sailfish Silica.

Задача: реализовать этот дизайн в моём существующем проекте на Aurora OS, сохранив весь
текущий функционал (см. functional-spec-for-design.md) и встроив новые экраны/фичи, которые
были добавлены в дизайне сверх исходного ТЗ:
- кастомный фон из галереи + полноэкранная ручная правка маски (кисть/ластик)
- превью-лента стилей (5 стилей) с debounce-выбором вместо одной кнопки
- слайдер силы стиля без повторного инференса (кэширование стилизованного слоя)
- панель "История изменений" со списком применённых шагов + кнопка "Сохранить как проект"
- новый экран "Пакетная обработка" (выбор нескольких фото + прогресс применения текущего
  проекта)
- toast-баннер для ошибок загрузки/сохранения и для "предыдущая операция отменена"

Требования к реализации:
- Используй существующие компоненты Sailfish Silica (Page, PageHeader, PullDownMenu,
  DockedPanel, SilicaFlickable, BusyIndicator, Dialog) — не изобретай велосипед там, где
  Silica уже даёт готовый паттерн (например bottom sheet для инструментов лучше делать через
  Dialog или DockedPanel, а не кастомным Rectangle).
- Все цвета/шрифты/отступы/радиусы бери из раздела "Design Tokens" в README — заведи их как
  единый QML-модуль (например Theme.qml с readonly property color/int), не хардкодь значения
  по разным файлам.
- Учитывай theme_pixel_ratio=1.25 и целевое разрешение 1600x2176 (планшет F+ T1100),
  поддержи и портретную, и альбомную ориентацию.
- Не блокируй UI-поток: любая обработка (Undo/Reset можно оставить синхронными, но
  Enhance/Фон/Стиль/маска/пакетная обработка) — через QThreadPool/QRunnable, с явной
  блокировкой панели инструментов на время isProcessing (см. README, "Сквозные механики").
- Подключай реальные вызовы C++ (pipelineManager.*, MLInferenceEngine, BackgroundWorker)
  там, где они уже реализованы по архитектурному плану; там, где бэкенда ещё нет (Фон/Стиль/
  пакетная обработка/ручная правка маски) — оставь UI полностью рабочим и готовым, вызовы
  оформи через понятный интерфейс/заглушку с TODO и понятной точкой интеграции, четко
  описанной в комментарии, чтобы бэкенд-часть можно было подключить позже без переделки UI.
- Не переноси инлайн-SVG иконки из HTML один в один — подбери/сгенерируй нормальный набор
  иконок в стиле Aurora (см. "Assets" в README про иконки и шрифты).

Сначала покажи мне план реализации (список файлов/страниц, которые создашь или изменишь, и
в каком порядке), не пиши сразу весь код.
```
