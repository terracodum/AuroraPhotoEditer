## 0. Задача

Нужно сформировать текстовый отчёт (docx) о разработке приложения. Ниже — весь фактический материал: назначение, архитектура, стек, структура кода, реализованные функции, тесты, сборка/упаковка, история разработки и открытые задачи. Разделы 9 содержит рекомендации по структуре самого отчёта — их можно адаптировать под требования пользователя (например, под шаблон вуза/практики), но не под выдуманные факты.

## 1. Общее описание проекта

**Aurora Photo Editor** — фоторедактор для мобильной операционной системы **Aurora OS** (российская ОС на базе Sailfish, используется на устройствах для корпоративного/государственного сектора). Приложение написано на **C++ (Qt 5)** для бизнес-логики и **QML (Sailfish Silica)** для интерфейса.

Ключевая идея продукта: пользователь выбирает фото из галереи устройства, применяет к нему обработку (в текущей версии — автоулучшение на основе классического CV, в разработке — фильтры на основе нейросетей: удаление/замена фона), может отменить (undo) или сбросить (reset) изменения, а затем экспортировать результат в галерею.

## 2. Архитектура

Проект строго разделён на два слоя:

1. **Frontend (QML + Sailfish Silica)** — только отрисовка интерфейса, без тяжёлой логики.
2. **Backend (C++ / Qt 5)** — вся бизнес-логика, обработка изображений, работа с файловой системой.

### Ключевые архитектурные решения

- **Мост C++ ↔ QML через `QQuickImageProvider`.** Класс `PipelineImageProvider` зарегистрирован по URL-протоколу `image://pipeline/`. Он напрямую отдаёт в QML текущее изображение (`QImage`) из `PipelineManager`, без промежуточного сохранения на диск — это позволяет мгновенно обновлять холст после каждой операции.

- **Многопоточность по паттерну Worker.** Работа с UI-потоком (главным потоком) для тяжёлых операций запрещена. Есть два независимых воркера на `QThread`:
  - `BackgroundWorker` — выполняет команды обработки изображения (`ImageEditorCommand::execute`) в фоне; поддерживает отмену (`cancel()`/`isCanceled()`) через `std::atomic<bool>`, чтобы не применять устаревший результат, если пользователь запустил новую операцию раньше, чем завершилась предыдущая.
  - `ExportWorker` — асинхронно сохраняет изображение в `PicturesLocation` в формате JPEG (качество 95), имя файла формируется с таймстампом (`AuroraPhotoEditor_yyyyMMdd_HHmmss.jpg`).

- **Command-паттерн для операций редактирования.** Абстрактный интерфейс `ImageEditorCommand` (`execute(QImage, MLProfiler*)`, `name()`) — единая точка входа для любых фильтров/эффектов. История изменений (стек команд с результатами) хранится в `PipelineManager::m_commandStack`, что даёт полноценные undo и reset «в один клик» без пересчёта с нуля.

- **Управление памятью.** В QML для динамического изображения на холсте явно отключено кеширование (`cache: false`), чтобы избежать утечек/распухания памяти при многократном наложении фильтров и постоянной смене источника картинки (`image://pipeline/current?t=timestamp`). Вся история undo/redo безопасно живёт на стороне C++, а не дублируется в QML.

- **Потокобезопасность `PipelineManager`.** Доступ к текущему/оригинальному изображению и стеку команд защищён `QMutex`/`QMutexLocker`. Это подтверждено юнит-тестом с 8 параллельными потоками, каждый из которых 100 раз подряд применяет команду и периодически делает undo (см. раздел «Тестирование»).

- **Профилирование ML-инференса (тайминги).** Любая операция обработки изображения обязана фиксировать время выполнения своих внутренних фаз (препроцессинг, инференс, постпроцессинг) через передаваемый объект `MLProfiler`. Тайминги считаются в микросекундах (`QElapsedTimer::nsecsElapsed() / 1000`) для каждой именованной фазы (`startPhase(name)` / `endPhase()`), а после завершения команды `BackgroundWorker` централизованно выводит структурированный JSON-лог (`MLProfiler::dumpLog`) вида:
  ```json
  {
    "event": "MLProfiler",
    "command": "Enhance",
    "phases": { "LAB_Conversion_and_CLAHE": 1234, "WhiteBalance_Correction": 456, "...": "..." },
    "total_us": 1690
  }
  ```
  Это заложено как единая точка сбора метрик производительности для любых будущих алгоритмов, в том числе нейросетевых.

## 3. Стек технологий и зависимости

- **ОС/SDK:** Aurora OS SDK (Qt 5.6), таргеты сборки — `armv7hl`, `aarch64`, `i486`.
- **Система сборки:** CMake (≥3.5), обнаружение зависимостей через `pkg-config`.
- **Библиотеки:**
  - Qt 5: Core, Network, Qml, Gui, Quick, Concurrent, LinguistTools (для переводов).
  - **OpenCV** — классическая обработка изображений (используется, например, в CLAHE-улучшении).
  - **ONNXRuntime** — инференс ML-моделей («умные» фильтры, в т.ч. сегментация фона на модели U2Net в разработке).
- **UI-фреймворк:** Sailfish Silica (компоненты `Page`, `PageHeader`, `DockedPanel`, `PullDownMenu`, `SilicaFlickable`, `BusyIndicator` и т.д.), `Sailfish.Pickers` — системный пикер изображений (`ImagePickerPage`).

## 5. Реализованный функционал (что фактически работает)

1. **Загрузка фото.** `PipelineManager::loadFromUri()` читает файл через `QImageReader` с учётом EXIF-ориентации (`setAutoTransform(true)`), конвертирует в `RGB888` (чтобы избежать «синевы» изображения) и устанавливает как оригинал.
2. **Выбор фото из галереи** через системный `ImagePickerPage` (Sailfish Pickers), запускается через Pull-down меню «Select Photo».
3. **Автоулучшение фото (`EnhanceCommand`)** — единственный полностью реализованный фильтр:
   - конвертация RGB → LAB;
   - CLAHE (адаптивная эквализация гистограммы) по L-каналу (clip limit 2.0, сетка 8×8) — вытягивает тени и света;
   - обратная конвертация LAB → RGB;
   - коррекция баланса белого по методу Gray World (выравнивание средних значений R/G/B каналов).
   - Каждая фаза обёрнута в замеры `MLProfiler`.
4. **Undo / Reset.** `undoLast()` откатывает последнюю команду по сохранённому в стеке результату; `resetToOriginal()` полностью очищает стек и возвращает исходное изображение. Оба потокобезопасны и уведомляют UI через Qt-сигналы.
5. **Отмена долгих операций «на лету».** Если пользователь запускает новую команду обработки, пока предыдущая ещё считается в фоне, `PipelineManager` отменяет предыдущий воркер (`cancel()` + `disconnect`), чтобы не перезаписать состояние устаревшим результатом.
6. **Экспорт результата.** Асинхронное сохранение текущего изображения в `PicturesLocation` в JPEG (качество 95) через отдельный поток (`ExportWorker`), с уведомлением об успехе/ошибке (`NoticePage`).
7. **UI-состояния:** заглушка «No photo selected» при отсутствии фото, индикатор загрузки (`BusyIndicator`) во время фоновой обработки (`pipelineManager.isProcessing`), плавное появление изображения (`FadeAnimation`).
8. **Инфраструктура под ML-фильтры (частично готова, не подключена к UI):**
   - `MLInferenceEngine` — инициализация окружения ONNX Runtime, загрузка `.onnx`-модели (`loadModel`), статические утилиты `prepareModelInput` (масштабирование входа под размер тензора модели, `Qt::FastTransformation`) и `upscaleResult` (масштабирование результата обратно до исходного разрешения, `Qt::SmoothTransformation`) — так называемый «scale module» (downscale/upscale).
   - Класс не связан ни с одной реальной моделью и ни с одной кнопкой UI — на макете нижней панели инструментов кнопки «Фон» / «Улучшение» / «Стиль» пока просто пишут в консоль (`console.log(...)`), реального экшена не имеют, кроме заготовленного `EnhanceCommand`.

## 6. Тестирование

Юнит-тесты на **QtTest** (`tests/test_pipeline.cpp`) покрывают `PipelineManager`:

- начальное состояние (нет изображения, пустой стек команд);
- установка исходного изображения и корректность сигналов `originalImageChanged`/`currentImageChanged`;
- применение тестовой команды (`FillColorCommand`) и проверка, что оригинал не меняется, а текущее изображение — меняется;
- undo нескольких команд подряд с проверкой промежуточных состояний и что лишний undo возвращает `false`;
- reset к оригиналу со сбросом стека;
- **потокобезопасность**: 8 потоков одновременно по 100 раз применяют команды и периодически делают undo — тест проверяет отсутствие падений и консистентность состояния после `resetToOriginal()`.

Сборка тестов подключена в `CMakeLists.txt` через `enable_testing()` + `add_subdirectory(tests)`.

## 7. Сборка и упаковка

- Сборка через **CMake**, зависимости ищутся через `pkg-config` (`auroraapp`, `auroraapp_i18n`, OpenCV, ONNXRuntime).
- Поддерживаемые целевые архитектуры: `armv7hl`, `aarch64`, `i486` (реальные и эмуляторные таргеты Aurora OS SDK).
- Упаковка в **RPM** (`rpm/*.spec`, `*.changes.in`) — стандартный формат дистрибуции приложений для Aurora OS.
- Локализация через файлы `.ts` (Qt Linguist), есть перевод на русский (`AuroraPhotoEditor-ru.ts`).
- Иконки приложения подготовлены для нескольких разрешений (86×86 … 172×172).
- Разработка ведётся в Aurora IDE (форк Qt Creator), сборка — «Build & Run» на выбранный таргет.

## 8. Статус разработки и незавершённые направления

На момент составления брифа (актуальная ветка `dev`, слияна с `main` по PR #37) в основную ветку влиты, в хронологическом порядке, следующие фичи (по git-логу):

1. Каркас проекта, права доступа (Media permission), запрет сетевого доступа в манифесте.
2. Интеграция `MLInferenceEngine` (ONNX Runtime + OpenCV).
3. `PipelineImageProvider` + исправление утечки памяти в провайдере.
4. Экспорт результата (`feat/exportresults`).
5. Базовый QML-интерфейс (`feat/QMLskelet`).
6. Background Task Manager (фоновые воркеры).
7. Безопасное завершение приложения (`graceful-shutdown`) — корректная остановка потоков в деструкторе `PipelineManager`.
8. `MLProfiler` — профилирование времени выполнения (`feat/timer`).
9. Downscale/upscale «scale module» в `MLInferenceEngine` (`feat/downscale-upscale`).
10. Автоулучшение фото `EnhanceCommand` (`feat/autocorrection`) — последняя влитая фича.

**В работе, но ещё не влито в `dev`/`main`** (существуют как отдельные незавершённые ветки/предложенные коммиты, в отчёте стоит явно пометить как «в разработке», а не как готовый функционал):

- Удаление/замена фона на модели **U2Net** (сегментация) через ONNX-инференс.
- Размытие краёв маски и многопоточное альфа-блендинг QImage (`feature/alpha-blend-optimization`).
- Кэширование масок и элементы управления фоном («background controls and mask caching»).
- Исправление «дыр» в пайплайне, восстановление механизма подключения OpenMP через Conan (`fix/pipeline-holes`).

**Известные ограничения текущей версии:**
- Кнопки «Фон» / «Улучшение» / «Стиль» на нижней панели инструментов — визуальные заглушки, не связаны с реальными командами (кроме `EnhanceCommand`, который существует, но пока не подключён к какой-либо из этих кнопок).
- Нет параметрических настроек (слайдеров) для `EnhanceCommand` — упоминается в `rules.md` как ожидаемая доработка.
- Единственный полностью работающий фильтр — автоулучшение (CLAHE + баланс белого), ML-фильтры на нейросетях в проде отсутствуют.
